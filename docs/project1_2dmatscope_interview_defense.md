## 0. 你必须先建立的项目定位

这个项目不能讲成“我训练了一个模型”。它应该讲成一个完整的视觉应用系统：

1. 输入端：显微相机实时采集二维材料图像。
2. 算法端：轻量级语义分割模型识别背景、单层、少层、多层。
3. 工程端：PyQt5 桌面系统负责显示、控制、异步推理、保存和录制。
4. 用户端：研究人员能实时观察材料层数分布，并保存检测结果。

最推荐的总述：

> 这个项目是一个面向二维材料显微图像的实时分割与可视化系统。我的工作不是只做模型训练，而是把显微相机、图像增强、RepELA-Net 分割模型、实时推理线程、结果叠加、保存和录像串成闭环。底层任务是语义分割，检测框和置信度是为了用户展示，从分割 mask 后处理得到的。

## 2. 项目两分钟版本

如果面试官让你详细介绍项目：

> 这个项目的背景是二维材料显微图像中，单层、少层、多层之间的差异主要体现在颜色、纹理和边界上，而且区域形状不规则，所以我没有把它作为普通目标检测问题，而是建模成语义分割问题。系统输入是显微相机实时画面，输出是背景、单层、少层、多层四类 mask。
>
> 硬件采集部分，我用 ctypes 封装 Toupcam SDK，实现相机枚举、打开、分辨率切换、曝光、增益、白平衡和 ROI 控制。相机工作在 pull mode callback 模式，SDK 有图像事件时回调置位，后台线程再拉取 BGRA 图像并转成 OpenCV BGR。
>
> 软件架构上，我用 PyQt5 做桌面界面。主线程只负责 UI，后台有相机抓帧线程和模型推理线程。相机线程只保留最新帧，推理线程也只处理最新提交帧，旧帧会被覆盖，这样即使高分辨率下推理较慢，界面也不会卡住。
>
> 模型部分是 RepELA-Net。前两层用 RepConv 提取局部纹理，后两层用 ELA 做轻量注意力和全局上下文建模，decoder 用 DW-MFF 动态多尺度融合，最后加边界增强模块来处理二维材料层间边界不明显的问题。推理时采用 512×512 滑窗，stride 默认 384，重叠区域做概率平均，再经过 EMA=0.3 时序平滑和 0.4 置信度阈值过滤。
>
> 最终系统支持左侧原图、右侧检测图双窗口显示，支持类别筛选，检测框、平均置信度和层数统计叠加，支持结果保存和 AVI 录制。模型最优测试 mIoU 是 84.64%，Pixel Acc 98.08%，Mean F1 91.16%，模型参数量 2.12M，大小 8.28MB。系统实测 640×480 下推理延迟 38-58ms，显示帧率 30.4-47.7 FPS，1280×960 下推理延迟 248-312ms。

## 4. 项目描述逐字应对

### 4.1 “开发”

面试官可能问：哪些是你开发的，哪些是现成库？

回答：

> PyTorch、OpenCV、PyQt5、Toupcam SDK 是基础工具和库；我开发的是把这些能力组合起来的系统，包括相机控制封装、实时线程架构、滑窗推理、结果叠加、保存逻辑，以及 RepELA-Net 模型训练和部署接口。

不要说 Toupcam SDK 是你写的；你写的是 SDK 的 Python 封装和应用层控制逻辑。

### 4.2 “面向 MoS2、WS2、Graphene 等二维材料”

面试官可能问：三种材料是不是同一个模型都能识别？

稳妥回答：

> 当前桌面系统默认是四分类：背景、单层、少层、多层，适合 MoS2 和 WS2 这种标签结构一致的材料。Graphene 在迁移学习代码里支持三分类或类映射，比如 BG、1L、>1L。严格来说，Graphene 如果接入桌面端，需要把类别数、颜色表和模型 head 动态配置化，这个是我能明确说明的工程边界。

面试官追问：那简历为什么写 Graphene？

回答：

> 因为训练和迁移实验框架确实考虑了 Graphene 目标域，包含 class map 和 fine-tune 流程。简历这句话表达的是项目面向这些二维材料场景，不代表当前 GUI 对所有材料已经做到零配置切换。

### 4.3 “二维材料显微图像”

要点：

1. 图像来自显微镜/显微相机。
2. 层数差异表现在颜色、亮度、纹理和边界。
3. 区域形状不规则，适合语义分割。

可回答：

> 二维材料显微图像和普通自然图像不同，目标不是“一个物体一个框”，而是材料薄片内部不同层数区域。单层、少层、多层的边界可能非常淡，颜色差异也受曝光、白平衡、基底和物镜倍率影响，所以我采用像素级分割，并且在系统里提供曝光、增益、白平衡和图像增强控制。

### 4.4 “实时识别系统”

面试官可能问：你怎么定义实时？

回答：

> 在这个系统里，实时包含两层含义。第一是相机画面实时刷新，用户移动样品时界面不能卡死；第二是检测结果尽快更新，但不要求每一帧都完整推理。系统采用异步推理和最新帧覆盖策略，所以显示实时性和推理实时性是分离的。

如果追问 1280×960 延迟 248-312ms 还算实时吗？

回答：

> 1280×960 下更准确地说是准实时检测，推理结果大约几百毫秒更新一次；但相机画面仍然实时刷新。640×480 下推理延迟 38-58ms，更接近实时检测。简历里我把两种分辨率的实测指标都列出来，就是为了说明不同分辨率下的性能边界。

### 4.5 “实现显微相机采集”

实现链路：

1. `ctypes.CDLL(DLL_PATH)` 加载 `nncam.dll`。
2. 用 `argtypes/restype` 声明 SDK 函数签名。
3. `Toupcam_EnumV2` 枚举设备。
4. `Toupcam_Open` 打开相机。
5. `Toupcam_put_eSize` 设置分辨率。
6. `Toupcam_StartPullModeWithCallback` 启动采集。
7. SDK 图像事件回调置位 `image_ready`。
8. 后台线程调用 `Toupcam_PullImage` 拉图。
9. BGRA 转 BGR，交给 UI 和推理模块。

面试官可能问：为什么用 pull mode callback？

回答：

> callback 只通知有新图像，不在回调里做重活；真正拉图在后台线程做。这样可以避免 SDK 回调里执行耗时操作导致阻塞，也方便和 PyQt UI 线程解耦。

### 4.6 “图像增强”

实现：

图像增强管线是：

1. USM 锐化：`GaussianBlur` 得到模糊图，`addWeighted` 强化高频边缘。
2. Gamma 校正：构造 0-255 LUT，调整亮暗。
3. CLAHE：转 LAB，只对 L 通道做局部直方图均衡，再转回 BGR。

面试官可能问：图像增强对模型有没有帮助？

回答：

> 当前系统里增强主要用于显示观察，不默认送入模型。这样做是因为模型训练时输入分布是原始显微图像，如果推理时人为改变对比度和颜色，可能造成域偏移。后续如果想把增强用于模型，需要在训练阶段同步加入相同增强策略。

### 4.7 “轻量化语义分割”

解释：

轻量化：模型参数、大小和计算量控制在可部署范围内。

语义分割：输出每个像素类别，而不是框。

回答：

> 我用的是语义分割，因为二维材料区域形状不规则，边界和面积很重要。轻量化的目标是让模型能接入实时系统，而不是只在离线评估中跑得准。RepELA-Small 的参数量是 2.12M，模型大小 8.28MB，适合进一步做端侧部署。

### 4.8 “检测结果可视化”

实现：

1. `pred_mask` 按类别映射颜色。
2. 与原图 alpha 融合。
3. 对每个类别做连通域分析。
4. 过滤面积小于 500 像素的小块。
5. 绘制外接框、类别名和平均置信度。
6. 左下角绘制 1L/FL/ML 数量统计。
7. 右上角叠加 FPS 和 Latency。

面试官可能问：检测框从哪里来？

回答：

> 检测框不是模型直接输出的。模型输出的是像素级 mask，我用连通域分析从每个类别的 mask 中找区域，然后对区域画外接矩形。这样既保留了分割能力，又能给用户类似检测框的直观展示。

### 4.9 “结果保存闭环”

实现：

保存包括两类：

1. 原图保存：保存相机当前帧。
2. 检测结果保存：保存叠加后的检测图。

两种模式：

1. 完整模式：图片里包含检测框、比例尺、FPS、Latency 和层数统计。
2. 简洁模式：图片只保留核心检测结果，另存同名 `.txt` 记录时间、分辨率、模型、FPS、Latency 和检测数量。

回答：

> 闭环指的是从采集、推理、显示到保存都在系统内完成。用户不需要再手动截图或另写脚本统计结果。

### 4.10 “判别二维材料单层、少层和多层区域”

回答：

> 类别定义是 Background、Monolayer、Fewlayer、Multilayer。训练 mask 的像素值就是 0、1、2、3。模型输出四通道 logits，softmax 后每个像素取最大概率类别。后处理再统计每类连通区域数量。

追问：为什么把少层单独作为一类？

回答：

> 从材料表征角度，单层、少层、多层的物理性质和后续应用价值不同。少层不是简单的背景或多层，显微图像上也有相对独立的颜色/纹理表现，所以单独建类。

## 5. 相机采集与硬件控制专项

### 5.1 “使用 ctypes 封装 Toupcam SDK”

可背回答：

> Toupcam SDK 提供的是 C 接口和动态库。Python 侧我用 ctypes 加载 `nncam.dll`，然后为每个 SDK 函数声明参数类型和返回类型，例如相机枚举、打开、关闭、设置曝光、拉取图像、白平衡回调等。这样 Python 的 PyQt 程序就能直接调用相机底层能力。

追问：ctypes 封装时最容易出什么问题？

回答：

> 主要是函数签名必须准确，比如指针、回调类型、宽字符字符串和返回值类型。如果签名错了，轻则返回错误，重则程序崩溃。另外回调函数对象必须在 Python 侧保存引用，否则可能被垃圾回收，导致 SDK 回调时出问题。

### 5.2 “相机枚举”

实现：

创建 `ToupcamInstV2 * TOUPCAM_MAX` 数组，调用 `Toupcam_EnumV2(devices)`，返回 count。如果 count 为 0，提示未找到相机。

回答：

> 枚举的目的不只是找到设备，还能拿到 display name 和 id，后续打开相机要用设备 id。

### 5.3 “分辨率切换”

实现：

UI 下拉框对应 `resolution_index`，调用 `Toupcam_put_eSize(self.handle, resolution_index)`，再用 `Toupcam_get_Size` 读实际 width/height。

回答：

> 分辨率切换不是简单 resize 图像，而是让相机输出不同分辨率。低分辨率适合实时，高分辨率适合保存和观察细节。

追问：为什么切换时要重启相机？

回答：

> 因为相机采集流运行中改分辨率可能导致 buffer 尺寸和当前拉帧逻辑不一致。先停采集，再设置分辨率，再启动，可以避免状态不一致。

### 5.4 “曝光/增益控制”

实现：

自动曝光：`Toupcam_put_AutoExpoEnable(handle, 1/0)`。

曝光时间：`Toupcam_put_ExpoTime(handle, time_us)`。

增益：`Toupcam_put_ExpoAGain(handle, gain_pct)`。

回答：

> 曝光和增益都影响图像亮度，但物理含义不同。曝光时间越长进光越多，但运动或抖动会更明显；增益放大信号，但也会放大噪声。所以系统里两者都开放给用户调节。

### 5.5 “白平衡调节”

实现：

手动：`Toupcam_put_TempTint(handle, temp, tint)`。

自动：`Toupcam_AwbOnePush(handle, callback, None)`。

回答：

> 二维材料层数识别很依赖颜色差异，白平衡不稳定会影响人眼观察，也可能影响模型输入。因此系统支持色温和 Tint 手动调节，也支持一键自动白平衡。

### 5.6 “支持曝光 1-2000ms、增益 100%-500%、色温 2000-15000、Tint 200-2500 调节”

回答：

> 曝光在 UI 里以 ms 为单位，SDK 内部用 us，所以设置时会乘 1000。色温和 Tint 来自 SDK 常量范围。所有参数设置前都会做范围限制，防止传入非法值。

追问：如果面试官问代码里默认 `expo_time_min=50us`，为什么简历写 1ms？

回答：

> SDK 底层可能支持更小粒度，但 GUI 控件面向用户以 1ms 为最小调节单位。简历写的是界面可调范围，不是 SDK 最底层极限。

## 6. 实时推理架构专项

### 6.1 “基于 PyQt5”

回答：

> PyQt5 负责桌面应用界面，包括按钮、滑块、下拉框、图像显示、状态栏、弹窗和线程信号。它适合快速构建实验室使用的桌面检测工具。

### 6.2 “相机抓帧、UI 刷新、模型推理分离”

架构：

1. `CameraController` 后台线程：只负责从 SDK 拉取最新帧。
2. `MainWindow` UI 主线程：用 QTimer 每 16ms 刷新显示。
3. `InferenceWorker` 推理线程：负责预处理、模型前向、滑窗融合、EMA 和阈值过滤。
4. 模型加载 QThread：避免加载大权重阻塞界面。

回答：

> 分离的核心原因是三类任务耗时和实时性要求不同。UI 线程必须轻，否则窗口会卡；相机采集要持续；模型推理耗时最大，所以必须放后台。

### 6.3 “最新帧覆盖旧帧”

实现：

相机侧只保存 `_latest_frame`。

推理侧只保存 `_frame`。

新帧到来时直接覆盖旧帧。

回答：

> 这是实时系统常用策略。它牺牲逐帧完整处理，换取低延迟和界面流畅。显微镜实时观察场景里，处理当前帧比处理历史帧更重要。

追问：如果用户想离线分析每一帧怎么办？

回答：

> 那就应该切换到离线处理模式，把视频保存下来后逐帧推理。实时模式和离线模式目标不同，实时模式优先低延迟。

### 6.4 “降低界面卡顿”

回答：

> 卡顿通常来自 UI 线程执行耗时任务，比如相机拉帧、模型前向或磁盘 IO。我的处理是把这些耗时任务放到后台线程，并用信号把结果传回 UI。UI 线程只做轻量显示更新。

### 6.5 “512×512 滑窗推理”

算法步骤：

1. BGR 转 RGB。
2. `to_tensor` 并用 ImageNet mean/std 归一化。
3. 若图像小于 512，用 reflect padding。
4. 根据 stride 生成 y/x 起点。
5. 强制加入最后一个窗口，保证边界覆盖。
6. 每个 crop 前向得到 logits。
7. softmax 得到类别概率。
8. 将概率累加到整图 `pred_sum`。
9. `count` 记录每个像素被预测次数。
10. `avg_probs = pred_sum / count`。
11. argmax 得到 mask，max 得到 conf_map。

追问：为什么重叠区域概率平均，而不是直接覆盖？

回答：

> 直接覆盖会导致窗口边界处结果不稳定。概率平均能融合多个窗口对同一像素的预测，减少拼接缝和边缘误差。

### 6.6 “stride=384”

回答：

> 默认 crop 是 512，stride 384，相当于 25% 重叠。重叠越多，边界更平滑、精度可能更高，但 crop 数量也更多，速度更慢。系统里还提供 fast、standard、precision 三种模式：512 无重叠、384 标准重叠、256 高精度重叠。

### 6.7 “EMA=0.3”

回答：

> EMA 是对推理概率图做时序平滑，不是训练权重 EMA。公式是当前概率占 0.3，历史概率占 0.7。这样可以减少显微画面轻微抖动造成的 mask 闪烁。

追问：为什么不是 0.5？

回答：

> 0.5 响应更快但抖动更明显，0.3 更稳。这个值是实时响应和稳定性之间的折中。如果样品移动很快，可以提高 alpha；如果画面静态观察，可以降低 alpha。

### 6.8 “0.4 置信度阈值过滤”

回答：

> 每个像素 softmax 最大值就是该像素置信度，低于 0.4 的像素归为背景。这个步骤可以过滤低置信散点，减少误检区域。

追问：阈值调高会怎样？

回答：

> 调高会减少误检，但可能漏掉颜色很淡的单层区域。调低会提高召回，但噪声更多。

## 7. RepELA-Net 模型专项

### 7.1 模型整体结构

可以画在纸上的结构：

```text
Input RGB
  ↓
ZeroPadChannel / ColorSpaceEnhancement: 3ch -> 4ch
  ↓
Stem Conv
  ↓
Stage1 RepConv
  ↓
Stage2 RepConv
  ↓
Stage3 ELA
  ↓
Stage4 ELA
  ↓
DW-MFF Decoder
  ↓
Boundary Enhancement
  ↓
Segmentation Head
  ↓
Upsample to original size
  ↓
4-class logits
```

回答：

> RepELA-Net 的设计思路是前浅层用卷积抓局部纹理，后深层用轻量注意力补全全局上下文，最后用动态多尺度融合恢复分割细节。

### 7.2 “RepConv”

回答：

> RepConv 是重参数化卷积。训练时它有 3×3、1×1 和 identity+BN 分支，多分支有助于训练表达；推理时通过 Conv-BN 融合、1×1 padding 成 3×3、identity 转成卷积核，把所有分支合成一个 3×3 卷积。这样推理时没有额外分支开销。

如果面试官要公式：

> Conv+BN 融合时，权重乘 `gamma / sqrt(var + eps)`，bias 为 `beta - mean * gamma / sqrt(var + eps)`。不同分支输出相加，等价卷积核和 bias 也可以相加。

### 7.3 “ELA”

回答：

> ELA 是 Efficient Linear Attention，用于在低计算量下引入全局建模。二维材料图像中，有的区域很小，有的区域很大，单纯局部卷积可能不够。ELA 用线性 attention 降低复杂度，并结合多尺度 pooling 捕获不同尺度上下文。

追问：为什么不全用 Transformer？

回答：

> 标准 Transformer 对高分辨率图像计算量大，而且数据量不大时容易过拟合。RepELA-Net 用卷积处理低层纹理，只在深层低分辨率特征上使用轻量注意力，是精度和效率的折中。

### 7.4 “DW-MFF”

回答：

> DW-MFF 是动态加权多尺度特征融合。浅层特征有细节，深层特征有语义。传统直接相加或 concat 权重固定，DW-MFF 给不同输入特征学习权重，并用 depthwise separable conv 做轻量 refine，让网络自己决定每个尺度的重要性。

### 7.5 “边界增强模块”

回答：

> 边界增强模块针对二维材料层间边界模糊的问题。它通过 depthwise conv 学习边缘响应，再结合通道注意力增强边界相关特征，帮助模型在单层、少层、多层交界处做更稳的分类。

### 7.6 “ColorSpaceEnhancement / ZeroPadChannel”

面试官可能从代码问到这个：

回答：

> 早期我考虑过把 HSV 饱和度作为第 4 通道，因为二维材料层数差异和颜色有关。默认 RepELA-Small 使用 ZeroPadChannel，也就是保持 4 通道结构但第 4 通道填 0。这样可以兼容 CSE 和非 CSE 的结构实验。简历主结果对应的是 RepELA-Small 默认配置，不强调 CSE。

## 8. 训练、数据和评估专项

### 8.1 数据集结构

回答：

> MoS2 数据集有原图目录和 mask 目录，mask 是单通道 PNG，像素值 0-3 对应背景、单层、少层、多层。split 文件固定 train、val、test，当前数量是 train 120、val 25、test 27。

### 8.2 数据增强

训练增强包括：

1. random crop 到 512。
2. 水平/垂直翻转。
3. 0/90/180/270 旋转。
4. brightness、contrast、saturation jitter。
5. gaussian blur。
6. 可选 CopyPaste 增强少数类。

回答：

> 因为单层和少层像素占比很低，数据增强主要是增加样本多样性，并缓解类别不均衡。

### 8.3 损失函数 Focal + Dice

回答：

> Focal Loss 解决类别不均衡和难样本问题，降低大量易分类背景像素的影响；Dice Loss 直接优化区域重叠，对分割任务友好。二者结合比单纯交叉熵更适合背景占比很高的二维材料分割。

类别权重：

背景约 74.86%，单层约 3.12%，少层约 2.46%，多层约 19.56%。所以少数类权重更高。

### 8.4 优化器和训练配置

回答：

> 训练默认 epochs=200，batch size=8，crop size=512，AdamW 优化器，初始 lr=6e-4，weight decay=0.01，cosine schedule，warmup 10 epoch。验证时对 full image 做 512 滑窗，stride 384。

### 8.5 mIoU

回答：

> IoU 是交集除以并集，mIoU 是所有类别 IoU 的平均。语义分割里 mIoU 比 Pixel Acc 更重要，因为背景像素很多，Pixel Acc 容易被背景主导。

### 8.6 Pixel Acc

回答：

> Pixel Acc 是所有像素中预测正确的比例。它能反映整体像素正确率，但在类别不平衡时不够敏感。

### 8.7 Mean F1

回答：

> F1 是 precision 和 recall 的调和平均，Mean F1 是对各类别 F1 求平均。它可以从另一个角度反映少数类识别效果。

### 8.8 “84.64% mIoU、98.08% Pixel Acc、91.16% Mean F1”

回答：

> 这组数值对应 RepELA-Small 在 test set 上的最优 seed=123 结果。我们还做了 3-seed 可复现性实验，平均 test mIoU 是 81.25±3.3%，最优 seed 达到 84.64%。

追问：为什么简历写最优，不写平均？

回答：

> 简历里写的是模型代表性最优结果，同时实验文档里也记录了三种 seed 的 mean±std。面试时我可以同时说明平均结果，避免只报最好 seed 带来的误解。

## 9. 系统集成专项

### 9.1 “训练模型集成到桌面端检测系统”

实现：

1. 用户点击 Load Model。
2. 后台 QThread 加载 `.pth` 或 deploy state_dict。
3. 根据 tiny/small/base 构造模型。
4. 根据 checkpoint 判断是否 use_cse、是否 deploy。
5. `load_state_dict` 加载权重。
6. `model.eval()`。
7. 把模型引用交给推理线程。

回答：

> 模型加载单独放线程，避免大权重加载时 UI 卡住。加载完成后通过信号回到 UI 线程更新状态。

### 9.2 “原图/检测图双窗口显示”

回答：

> 左侧显示相机原始或增强画面，右侧显示模型检测叠加结果。这样用户可以直接对比原始显微图和模型判断结果。

### 9.3 “类别筛选”

回答：

> 类别筛选用于只看某一种层数，比如只显示单层区域。实现上不是重新推理，而是在可视化阶段控制 visible_classes，只绘制指定类别。

### 9.4 “检测框”

回答：

> 检测框来自 mask 后处理。对每个类别二值 mask 做 connected components，得到每个连通域的 left、top、width、height，再画外接矩形。

### 9.5 “置信度”

回答：

> 像素置信度来自 softmax 最大概率。区域置信度是该连通域内所有像素 conf_map 的平均值。它不是严格校准概率，但能反映模型对该区域预测的相对把握。

### 9.6 “层数统计叠加”

回答：

> 层数统计是每个类别保留下来的连通域数量，比如 Monolayer:1、Fewlayer:1、Multilayer:2。它帮助用户快速判断当前视野内不同层数区域数量。

追问：这个数量等于真实晶片数量吗？

回答：

> 不完全等价。它是基于分割连通域的区域数量。如果一个材料区域被分割成多个断裂连通域，统计数会偏多；如果多个区域连接在一起，统计数会偏少。所以它是辅助统计，不是严格物理计数。

### 9.7 “结果保存”

回答：

> 保存支持原图和检测结果图。完整模式把比例尺、FPS、Latency 和统计信息画到图上；简洁模式另存 `.txt` 元数据，便于论文或报告使用。

### 9.8 “AVI 录制”

回答：

> 使用 OpenCV `VideoWriter`，分别录制相机画面和检测结果画面，编码格式是 XVID，文件保存在 recordings 目录。录制时如果已有实际 FPS，就用实际 FPS，否则默认 15 FPS。

## 10. 性能指标专项

### 10.1 “640×480 分辨率下推理延迟 38-58ms”

回答：

> 这是系统保存结果时记录的实际推理延迟。640×480 下图像尺寸较小，滑窗数量少，所以延迟较低。

### 10.2 “显示帧率 30.4-47.7 FPS”

回答：

> 这个 FPS 是界面显示/采集刷新帧率，不是模型每秒推理次数。因为相机显示和模型推理是异步的，显示 FPS 可以高于推理 FPS。

### 10.3 “1280×960 下延迟 248-312ms”

回答：

> 1280×960 下默认 512 crop、stride 384，大约需要 9 个窗口前向，所以延迟比 640×480 明显增加。这个指标说明系统在高分辨率下是准实时，而不是每帧都 30FPS 推理。

### 10.4 如果面试官质疑性能

回答：

> 这个质疑是合理的，所以我会区分显示实时性和推理实时性。系统设计上保证相机画面不卡顿，推理结果异步更新。低分辨率下接近实时检测，高分辨率下换取更高细节和更高延迟。后续优化方向包括降低推理输入尺寸、ONNXRuntime/TensorRT/RKNN、减少滑窗重叠、模型量化和缓存 crop 坐标。

## 12. 高频拷打题库

### Q1：你的项目到底是检测还是分割？

回答：

> 底层是语义分割，模型输出每个像素的类别。检测框是从分割 mask 做连通域分析得到的可视化结果。简历里写检测结果可视化，是指把分割结果以检测框、置信度和统计信息的形式展示出来。

### Q2：为什么不用 YOLO？

回答：

> YOLO 适合规则目标的框定位，但二维材料层数区域形状不规则，边界信息重要。只用框无法准确表达单层、少层、多层区域。语义分割更适合像素级层数判别。

### Q3：RepELA-Net 和普通 UNet 有什么区别？

回答：

> UNet 主要是 encoder-decoder 和 skip connection。RepELA-Net 在 encoder 里用了 RepConv 和 ELA：RepConv 兼顾训练表达和推理融合，ELA 引入轻量全局上下文；decoder 用 DW-MFF 动态多尺度融合和边界增强，更针对二维材料多尺度和细边界问题。

### Q4：为什么 Pixel Acc 很高，mIoU 没有同样高？

回答：

> 因为背景像素占比很高，Pixel Acc 容易被背景主导。单层和少层像素少，预测错会明显影响 mIoU，但对 Pixel Acc 影响不一定大。所以分割任务更应该看 mIoU 和 per-class IoU。

### Q5：你怎么处理类别不均衡？

回答：

> 数据层面用随机 crop、翻转、旋转、亮度/对比度/饱和度增强，可选 CopyPaste 增强少数类；损失层面用 Focal Loss 降低易分类背景影响，用 Dice Loss 提高区域重叠优化，并设置类别权重。

### Q6：滑窗推理会不会有拼接缝？

回答：

> 可能有，所以我用重叠滑窗和概率平均，而不是直接覆盖。重叠区域多个窗口预测结果取平均，可以减轻边界拼接问题。

### Q7：EMA 会不会导致响应变慢？

回答：

> 会有一点延迟，这是稳定性和响应速度的折中。显微观察多数时候画面移动不剧烈，EMA 能减少闪烁。如果快速移动样品，可以提高 alpha 或关闭 EMA。

### Q8：0.4 阈值怎么来的？

回答：

> 它是工程经验阈值，用来过滤低置信背景噪声。阈值过高会漏掉单层，过低会增加散点误检。后续可以在验证集上通过 PR 曲线或 mIoU/召回权衡系统地选择。

### Q9：检测框最小面积 500 为什么这么设？

回答：

> 这是为了过滤小噪声区域。二维材料有效区域通常有一定面积，过小连通域大多是噪声或边界碎片。500 是工程阈值，后续可以根据倍率和分辨率做自适应。

### Q10：为什么 640×480 更快？

回答：

> 因为滑窗数量少。高分辨率下要切更多 512 crop，每个 crop 都要模型前向，所以延迟随窗口数量上升。

### Q11：有没有端侧部署？

回答：

> 这个桌面系统主要是 PyTorch/PyQt5 版本。另一个本地项目里做过 RepELA-Net 的 ONNX 导出和 RKNN 转换，并在 OrangePi/RK3588 上用 RKNNLite 加载推理。对于 2DMatScope，如果要端侧化，可以复用这个转换流程。

### Q12：你项目最大的不足是什么？

回答：

> 第一，GUI 和研究模型代码耦合还比较强，后续应该抽出统一 inference API；第二，滑窗逻辑在训练、评估、GUI 中有重复，应该统一；第三，Graphene 这种不同类别数目标域还没在 GUI 层完全动态配置；第四，高分辨率下推理延迟较大，需要进一步做 ONNX/RKNN/TensorRT 或降分辨率优化。

## 14. 最需要背熟的三段话

### 14.1 项目难点

> 这个项目难点不只是训练模型，而是把模型放进真实显微相机系统里稳定运行。二维材料层数差异细、边界模糊，所以算法上要做像素级分割；显微图分辨率高，所以推理上要做滑窗和概率融合；实时系统不能卡 UI，所以工程上要做多线程和最新帧策略；最后用户需要可解释结果，所以还要把 mask 转成检测框、置信度、层数统计和可保存结果。

### 14.2 你的贡献

> 我的贡献包括三部分：第一，模型侧完成 RepELA-Net 的训练、评估和轻量化指标验证；第二，系统侧用 ctypes 接入 Toupcam SDK，用 PyQt5 实现相机控制和双窗口检测界面；第三，推理侧实现异步滑窗推理、EMA 平滑、置信度过滤、连通域可视化、结果保存和 AVI 录制，把模型真正接到实时显微图像工作流中。

### 14.3 项目边界

> 我不会把这个项目说成万能检测系统。它底层是四分类语义分割，最成熟的是 MoS2/WS2 这类四类标签场景；Graphene 在迁移学习框架中支持，但 GUI 还需要动态类别配置。性能上，640×480 接近实时，高分辨率下是准实时。精度上，RepELA-Net 的优势是轻量和可部署，不是绝对超过所有预训练 baseline。
